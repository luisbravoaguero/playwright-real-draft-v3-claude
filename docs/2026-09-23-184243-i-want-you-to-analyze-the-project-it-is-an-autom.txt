  Business areas covered: policy quote and issuance for Auto (new and used, with
  inspection), SOAT, SCTR (short and regular period), Vida Ley, Accidentes,

  and Riesgos Generales. It also covers the Constancias SCTR / SCTR Minería / 
  Vida Ley module (declaración, inclusión, manual, reemplazo, reimpresión,
  anulación, mes vencido) and Inspección de Autos.

  How one scenario runs

  1. The TestNG data provider hands scenarios to threads. The dp.threads setting
     controls how many (default 1; Jenkins uses 2).
  2. Hooks.@Before sets up the screenshot sink, then DriverFactory.init()
     creates a full Playwright instance, browser, context and page for that 
     scenario, stored per thread. It also creates the Extent test.
  3. Step classes get a PageProvider and a ScenarioContext through PicoContainer
     and build their page objects in the constructor.
  4. Page methods follow an action + UiSync.waitForAppIdle pattern: they wait
     until the spinner is hidden and stays hidden for 250 ms. Harder transitions
     use race utilities such as FirstAppearanceRace, which reports whether
     error, success or timeout appeared first and stayed stable.
  5. @After takes a screenshot on failure, then DriverManager.cleanup() and
     clears the per-thread state.

  CI pipeline (JenkinsCI)

  1. Discover: a dry run of Cucumber with the chosen tags writes JSON, which is
     turned into a list of feature:line entries.
  2. Split: the list is cut into groups of 2, and each group gets its own 
     Kubernetes pod, all running in parallel. Each pod runs 2 threads.
  3. Per pod: runs the tests, removes  - #1 suffixes from JUnit test names (for
     Octane), publishes JUnit, and stashes extent.json.
  4. Merge: ExtentJsonMergeMain is run through exec:java. It merges every pod's
     JSON into one Spark HTML report, which is then passed to publishHTML and
     archived.

  This is a well-designed setup: splitting across pods with a merged Extent
  report is not common, and it scales well.

  3. Strengths

  - Clean layering: configuration, driver, pages, steps and reporting are
    separate. The ArtifactSink interface stops src/main from depending on
    Cucumber.
  - Built to run in parallel: driver objects and Extent tests are stored per
    thread, with scenario state injected by PicoContainer. ScenarioContext
    documents why it is thread-safe.
  - Modern locators: about 580 getByRole, 195 getByText and 83 getByLabel calls,
    against only 27 XPath uses.
  - Synchronization designed around the app: the spinner-wave plus quiet-period
    approach and the first-appearance races fit an Angular app with many modals.
  - Configuration follows 12-factor style: any key can be overridden with -D or
    an environment variable.
  - Rich evidence: screenshots inside each step node, named checkpoints, and a
    readable console log with per-step timings.
  - Living docs: the docsFeatures/*.md files describe each flow in business
    terms.

  4. Findings and risks (most important first)

  🔴 High

  1. Plain-text credentials and an internal URL in the repo. global.properties
     contains user.email=WEBMASTER and user.password=Mapfre123.. Because
     ConfigManager already accepts environment variables, the fix is to remove
     these values and set USER_PASSWORD from a Jenkins credential. Treat this
     password as exposed and rotate it. A second problem: LoginPage reads the
     values through ConfigManager.getProperty, which skips the -D/ENV override.
     It needs to switch to getGlobal for the override to work.
  2. RandomData returns the same values every time. rnd() builds new 
     Random(SeedManager.seed()) on every call, with the same seed per thread,
     and SeedManager.clear() is never called. As a result, numeric(),
     fullName(), randomPlate(), randomVehicleIdentificationNumber() and
     randomEngineNumber() return the same value on every call in a thread, and 
     in every later scenario on that thread. Two used-auto scenarios on one
     thread would register the same plate, VIN and engine number. Fix: keep one
     Random per thread and clear the seed in @After. idDocumentPeru is not
     affected because it uses ThreadLocalRandom.
  3. The runner hardcodes tags = "@riesgosgenerales". Running mvn test locally
     without -Dcucumber.filter.tags runs only that one module. Jenkins always
     passes tags, so CI works, but this is easy to miss.

  🟠 Medium

  4. Two screenshots per step. Hooks.@AfterStep and
     ExtentCucumberStepsPlugin.onTestStepFinished both take a full screenshot
     after every step, and ExtentEvidence.shot calls add more. This slows runs
     and makes reports large (base64 images inside the JSON that gets merged).
  5. A full Playwright instance and browser start for each scenario. This
     isolates scenarios well but costs about 1–2 s per scenario. A lighter
     option is one browser per thread with a new BrowserContext per scenario.
  6. DriverManager.cleanup() is not exception-safe. If page.close() throws, the
     browser and Playwright process leak and the per-thread values are never
     removed.
  7. ElementAsserts throws away the original error. It throws new 
     AssertExceptions(message) without the cause, so the Playwright call log and
     locator details are lost, which makes failures harder to diagnose.
  8. Fixed waits and polling. There are 54 waitForTimeout calls, 2 Thread.sleep
     in DocumentoSoatPage, and waitRandomBetween. clickMenuOption uses
     JavaScript clicks plus 3.5 s of fixed waits.
  9. JavaScript built by string concatenation. In clickMenuOption, '" + menuName
     + "' breaks if a menu name contains a quote. Pass it as an evaluate
     argument instead.
  10. Broad exception handling. There are 143 catch (Exception …) blocks and 73
      System.out.println calls that bypass SLF4J and the reports.

  🟡 Low / maintainability

  11. The step-definition style creates very long steps. Some steps take 16
      parameters (for example the SCTR "Datos de la empresa" step). All 81
      scenarios are Scenario Outlines, mostly with a single Examples row, and
      there are no Background blocks even though every scenario starts with the
      same login and navigation. Data tables or a data model would make steps
      shorter and easier to reuse.
  12. BasePage is a large catch-all (889 lines). It has many near-duplicate
      helpers (fillInputIfEnabledAndSync, fillInputIfEnabledBlurAndSync,
      fillInputValueIfEnabledAndEmptyAndSync…) and names mixing English and
      Spanish (seleccionarOpcionPorTexto next to selectOptionByTextInsensitive).
      Moving these into components (the components/material package is a good
      start) and a small fluent API would help.
  13. Inconsistent tags and naming. Tags include @regresion and @Regresion, and
      the Jenkins default is @emisionsctr. There are typos in folder and step
      names (contaciasSctrVidaLey, riegosgenerales, emsion, fomrulario, codgio,
      valdiar), and some leftover files (Formato_trama_sctr - copia.xls).
  14. Maven metadata is still placeholder. It shows groupId org.example,
      artifactId playwright-project-try-02. There is no Maven Wrapper and no
      dependency or plugin version enforcement. app.url.dev and app.url.prod
      point to saucedemo.com, and implicitWait in driver.properties is never
      used.
  15. Hardcoded relative paths. TemplateFactory uses Paths.get("src/test/…"),
      which ties runs to the working directory, even though TestResourceFiles
      (classpath-based) already exists.
  16. Report placement. ExtentJsonMergeMain and the reporting classes are in
      src/test, while ArtifactSink is in src/main. This works, but the report
      module is split across both. Duplicate or unused code:
      ExtentCucumberStepsPlugin.onTestRunFinished and
      ExtentLifecycleHooks.@AfterAll both flush, and SchedulingState is used by
      only one step class.
  17. No automated checks on the framework itself. There are no unit tests for
      the utilities (races, DateUtils, RandomData), no static analysis
      (Checkstyle, SpotBugs) and no README or CLAUDE.md. .gitignore exists, but
      the folder here is not a git repository.

  5. Recommended next steps

  1. Remove the credentials from global.properties, rotate the password, and
     switch LoginPage to getGlobal.
  2. Fix RandomData/SeedManager: one Random per thread, with the seed cleared in
     @After.
  3. Remove the hardcoded tag from the runner, or default it to something
     harmless like not @wip.
  4. Take one screenshot per step (remove the duplicate @AfterStep capture) and
     make cleanup() and ElementAsserts safer.
  5. Move to one browser per thread and one context per scenario, and replace
     fixed waits with state-based waits.
  6. Refactor gradually: Background for login, shorter steps, split BasePage
     into components, and one tagging convention.

  3. When to write \\

  In a .properties file a single \ is an escape character, so the file reader
  removes it or changes what follows. You only need to care if your password 
  contains a backslash.

  Suppose your real password is Mapfre\2025.

  ┌────────────────────────────┬─────────────────────────────┬──────────────┐
  │ What you write in the file │   What the code actually    │   Correct?   │
  │                            │          receives           │              │
  ├────────────────────────────┼─────────────────────────────┼──────────────┤
  │ user.password=Mapfre\2025  │ Mapfre2025 (the \           │ ❌ login     │
  │                            │ disappears)                 │ fails        │
  ├────────────────────────────┼─────────────────────────────┼──────────────┤
  │ user.password=Mapfre\\2025 │ Mapfre\2025                 │ ✅           │
  └────────────────────────────┴─────────────────────────────┴──────────────┘

  Two more cases, less common:
  - A space at the start of the password. Write user.password=\ abc to get  abc.
  - A password ending in a backslash, like abc\. Write abc\\. A single \ at the
    end of a line means "continue on the next line".

  Characters like ., !, @, #, $, %, = or : in the middle of the password don't
  need escaping. Your old password Mapfre123. could be written exactly as it
  was.

  These escaping rules apply only to the file. Environment variables in Jenkins
  take the value exactly as typed, with no escaping.
